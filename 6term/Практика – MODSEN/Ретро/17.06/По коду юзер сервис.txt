Проект — Spring Boot приложение для управления пользователями с использованием Spring Security и JWT для аутентификации/авторизации. Реализует регистрацию, логин, управление пользователями и ролями, документировано через Swagger.


AppConfig.java
Зачем: Настраивает бины приложения, предоставляет PasswordEncoder для хеширования паролей.
Что делает: Создает бин BCryptPasswordEncoder для безопасного хранения паролей.
Связь: Используется в UserService для хеширования паролей при регистрации/обновлении.


SecurityConfig.java
Зачем: Настраивает Spring Security для защиты API.
Что делает: Отключает CSRF, задает правила доступа (открытые /api/auth/register, /login, Swagger; защищенные /api/users для ADMIN), использует stateless-сессии, добавляет JwtRequestFilter.
Связь: Интегрирует JwtAuthenticationEntryPoint, JwtRequestFilter, UserService, PasswordEncoder для аутентификации/авторизации.


AuthController.java
Зачем: Обрабатывает запросы на регистрацию и логин.
Что делает: /register создает пользователя, /login выдает JWT-токен.
Связь: Использует UserService для регистрации, AuthenticationManager для проверки логина, JwtUtil для генерации токена.


UserController.java
Зачем: Управляет пользователями (для ADMIN).
Что делает: Реализует CRUD (GET, PUT для пользователей, PATCH для смены ролей) с ограничением доступа через @PreAuthorize("hasRole('ADMIN')").
Связь: Работает с UserService для бизнес-логики, защищен SecurityConfig.


JwtAuthenticationEntryPoint.java
Зачем: Обрабатывает ошибки аутентификации.
Что делает: Возвращает HTTP 401 (Unauthorized) при невалидном/отсутствующем JWT.
Связь: Используется в SecurityConfig для обработки исключений.


JwtRequestFilter.java
Зачем: Проверяет JWT в запросах.
Что делает: Извлекает токен из заголовка Authorization, валидирует через JwtUtil, устанавливает контекст безопасности.
Связь: Работает с JwtUtil (валидация) и UserService (загрузка UserDetails), добавлен в SecurityConfig.


JwtUtil.java
Зачем: Управляет JWT-токенами.
Что делает: Генерирует, валидирует токены, извлекает данные (например, username).
Связь: Используется в AuthController (генерация токена) и JwtRequestFilter (валидация).


UserService.java
Зачем: Реализует бизнес-логику и UserDetailsService для Spring Security.
Что делает: Регистрирует, обновляет пользователей, меняет роли, загружает UserDetails для аутентификации.
Связь: Использует UserRepository для доступа к БД, PasswordEncoder для хеширования, интегрирован в SecurityConfig и контроллеры.


UserRepository.java
Зачем: Интерфейс для работы с БД (JPA).
Что делает: Предоставляет методы для CRUD (findByUsername, findByEmail, save).
Связь: Используется UserService для сохранения/поиска пользователей.


UserServiceApplication.java
Зачем: Главный класс приложения.
Что делает: Запускает Spring Boot, настраивает Swagger и JWT-документацию.
Связь: Инициализирует весь контекст приложения.


Дополнительные вопросы

serialVersionUID
Что: Уникальный идентификатор версии класса для сериализации.
Зачем: В JwtAuthenticationEntryPoint (реализует Serializable) обеспечивает совместимость при десериализации.
Где: private static final long serialVersionUID = -7858869558953243875L.


Где хешируется пароль
в бине AppConfig через BCrypt
В UserService:
registerUser: user.setPassword(passwordEncoder.encode(registerRequest.getPassword())).

updateUser: user.setPassword(passwordEncoder.encode(userDetails.getPassword())) (если пароль передан).


Что такое BCrypt
Что: Алгоритм хеширования паролей с солью и адаптивной сложностью.


Что такое bean

Зачем: Позволяет Spring создавать, конфигурировать и внедрять зависимости (например, PasswordEncoder, UserService).

Где: Определяются через @Bean (в AppConfig, SecurityConfig) или аннотации (@Component, @Service, @Repository).

DTO: Зачем и связь с БД
Зачем: Скрывают структуру сущностей, обеспечивают безопасность (не передают пароль), валидацию, гибкость API.


Хранение данных пользователей
Где: В PostgreSQL, таблица users (сущность User с полями id, username, password, email, role).
Как: Доступ через UserRepository (JPA).


Механизмы синхронизации

Что: Транзакции через @Transactional в UserService (registerUser, updateUser, updateUserRole).
Зачем: Гарантируют атомарность операций с БД.


Аутентификация:
Что: Проверка, кто вы (подтверждение личности).
Авторизация:
Что: Проверка, что вы можете делать (доступ к ресурсам).
Валидация:
Что: Проверка корректности данных.

JSON: расшифровка и суть
Расшифровка: JSON — JavaScript Object Notation (нотация объектов JavaScript).

JSON Web Token — компактный токен в формате JSON, состоящий из трех частей: Header, Payload, Signature (закодированы в Base64, разделены точками).
Зачем:
Аутентификация: Хранит данные пользователя (например, username) для проверки личности.
Авторизация: Может содержать роли (например, ROLE_ADMIN) для ограничения доступа.
Stateless: Не требует хранения сессий на сервере, упрощает масштабирование.
