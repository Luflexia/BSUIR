# От хранения данных к управлению информацией (краткие заметки)

## Часть 1

### 1. Компоненты блочной системы хранения
- Внешний интерфейс
- Кэш-память
- Внутренний интерфейс
- Физические диски

### 2. Алгоритмы интеллектуального кэширования
- LRU (Least Recently Used) — замещает наименее востребованные страницы.
- MRU (Most Recently Used) — замещает самые недавно использованные страницы.
- Упреждающая выборка (pre-fetch) — предварительное считывание смежных блоков.
- Отложенная запись (write-back) — данные в кэш с подтверждением, потом на диск.
- Сквозная запись (write-through) — данные в кэш и сразу на диск.
- Ленивый сброс (idle flushing), сброс на верхнем уровне (high watermark flushing), принудительный сброс (forced flushing) — для управления сбросом.

### 3. Механизм защиты данных кэш-памяти
- Зеркальное кэширование — дублирование данных в двух местах.
- Аварийное сохранение — сброс на SSD или батареи при сбое.
- Флаги статуса — отслеживание записи на диск.

### 4. Традиционное и виртуальное выделение ресурсов
- Традиционное: Полная аллокация LUN из RAID-наборов; предсказуемая производительность, но недоиспользование.
- Виртуальное: Тонкие LUN (thin) с overprovisioning из пула; экономия пространства, динамика, но возможны колебания производительности.

### 5. Расширение томов
- На уровне хоста: Через диспетчер томов — несколько физических дисков в логический том.
- На уровне массива: МетаLUN — объединение LUN (concatenation для емкости, striping для производительности).

### 6. Многоуровневое хранение на уровне тома и элемента тома
- Уровень тома: Перемещение всего LUN между уровнями (SSD → FC → SATA) по активности.
- Уровень элемента тома: Разбиение на сегменты (8 Мбайт), перемещение активных на быстрые, неактивных — на медленные.

### 7. Многоуровневая кэш-память
- Первичный: DRAM (быстрый).
- Вторичный: SSD (расширение объема).
- Активные данные в DRAM, менее — в SSD.

### 8. Серверное кэширование на основе флэш-памяти
- Флеш-карта в сервере как вторичный кэш после DRAM.
- Ускоряет приложения локально, расширяет кэш массива.

## Часть 2

### 1. Компоненты NAS
- NAS-надстройка: CPU, память, NIC, ОС NAS, протоколы (NFS, CIFS), интерфейсы (FC, SAS).
- Хранилище: Массив дисков (внутренний/внешний).

### 2. Архитектура NAS
- Клиенты по IP-сети к надстройке.
- Надстройка конвертирует файловые запросы в блочные I/O.
- Совместный доступ, единая ОС.

### 3. Методы доступа к файлам в системе NAS
- NFS — для UNIX/Linux, монтирование.
- CIFS/SMB — для Windows, совместное использование.
- FTP/SFTP — передача файлов.
- DFS — распределенная система.
- P2P — прямой обмен.

### 4. Операции ввода-вывода в системе NAS
- Клиент отправляет файловый запрос по TCP/IP.
- NAS конвертирует в блочный I/O, обрабатывает в хранилище.
- Возврат в файловом формате (по имени/пути на блоки).

### 5. Виртуализация на уровне файлов
- Глобальное пространство имен, логический пул.
- Перемещение файлов без прерывания, клиенты используют логические пути.

### 6. Многоуровневое хранение
- Уровни: SSD (tier 0), FC/SAS (tier 1), SATA (tier 2).
- Автоматическое перемещение по политикам (частота доступа).

### 7. Сценарий использования NAS
- Совместное использование файлов в офисе (документы, медиа).
- Для неструктурированных данных, виртуализации файлов, миграции.

### 8. Причины использования устройств OSD
- Безопасность, надежность (шифрование, репликация).
- Масштабируемость (flat namespace).
- Независимость от платформы, API-доступ.
- Для архивации фиксированного контента (CAS).

### 9. Сравнение иерархической файловой системы и одноуровневого адресного пространства
- Иерархическая: Дерево каталогов, пути; легко для пользователей, но ограничена масштабом.
- Одноуровневое (OSD): Плоское, по ID; масштабируемо, самоуправление, для больших данных.

### 10. Ключевые компоненты OSD
- Узлы: Метаданные (ID, mapping) и хранения (диски).
- Закрытая сеть для связи.
- Хранилище: Недорогие диски.

### 11. Ключевая функциональность OSD
- Генерация ID (hash).
- Хранение объектов с метаданными.
- Самоуправление (защита, репликация).
- API-доступ (REST, SOAP).

### 12. Внедрение объектных систем хранения
- Узлы для метаданных/хранения.
- CAS для уникальных адресов.
- Интеграция через API, масштабирование без downtime.

### 13. Процесс сохранения и извлечения данных в объектной системе хранения
- Сохранение: Файл → данные/метаданные → ID (hash) → хранение → подтверждение.
- Извлечение: Запрос по имени → ID от метаданных → объект по ID → возврат.

### 14. Шлюз объектной системы хранения
- Интерфейс для конвертации запросов (file/block) в объектные.
- Например, EMC VNX Gateway: Управляет NAS/OSD, доступ через NFS/CIFS/S3.
